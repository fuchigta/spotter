# unwanted-files

コミットしてはいけないもの（ローカルのデータベース・ログ・シークレット・巨大ファイルなど）の
混入を検知する検査です。

起動粒度は [per-commit](../granularity.md) 固定です。範囲内のコミットごとに 1 回ずつ見るため、
後から該当ファイルを消しても履歴には残った状態になり、検査は失敗し続けます。

## 設定

```yaml
checks:
  unwanted-files:
    type: unwanted-files
    max_bytes: 1048576
    deny:
      - { paths: '*.log', reason: 'ログファイル' }
      - { paths: '.env', reason: '環境変数・シークレット' }
      - { paths: '.env.*', reason: '環境変数・シークレット' }
      - { paths: '*.pem', reason: '秘密鍵' }
```

### `deny[].paths` / `deny[].reason`（両方必須）

拒否するファイルの [glob パターン](../glob-patterns.md)と、違反表示に出す理由。両方無いと
起動時にエラーになります。`deny` は上から順に評価し、最初に一致したルールの `reason` を
使います。

### `max_bytes`（省略可、既定 0 = 無効）

これを超えるサイズの blob を含む変更を拒否します。`deny` のどのルールにも一致しなかった
ファイルだけがサイズ判定の対象になります（`deny` に明示的に載せたファイルは、理由も
`deny` 側のものが優先されます）。

## 挙動の細部

- 対象は追加・変更・コピー・改名されたファイル（削除は対象外）です。
- ファイルサイズは、比較対象のコミット時点の blob サイズです（staged モードならステージ
  済みの中身、range モードなら比較先コミット時点の中身）。
- `deny` にも `max_bytes` にも触れなければ違反 0 件で成功します。

## 免除

[免除トレーラ](../exemptions.md)が使えます。既定のトレーラ名は `Unwanted-Files` です
（キー名を変えていれば、そのキーから生成された名前になります）。ただし per-commit 粒度
なので、免除トレーラは違反した**そのコミット自身**のメッセージに書く必要があります。
range モードで後続のコミットに書いても、既に履歴に残った違反コミットは免除されません。
