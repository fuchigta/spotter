# 免除トレーラ

検査ごとに、コミットメッセージ本文の**トレーラ**で免除できます。

```
Doc-Sync: skip 対応するドキュメントは無い
```

## なぜ環境変数ではなくコミットメッセージなのか

免除の判断根拠をコミットメッセージに置いているのは、**手元のフックと CI が同じコミット
メッセージを見る**ようにするためです。もし環境変数（例: `SKIP_DOC_SYNC=1`）で免除できる
仕組みにすると、ローカルでは通ったのに、その環境変数を設定していない CI では落ちる
（あるいはその逆）という状態になり得ます。コミットメッセージなら、手元で書いた免除の
判断がそのまま git 履歴に乗って CI にも届くので、判断がずれません。

## トレーラ名

既定では `checks.<キー>` のキー名をタイトルケースに変換したものです。

```
doc-sync            → Doc-Sync
commit-types-consistency → Commit-Types-Consistency
```

`checks.<key>.exempt.trailer` で明示的に上書きできます。

```yaml
checks:
  doc-sync:
    type: doc-sync
    exempt:
      trailer: Custom-Skip
```

## 有効/無効

```yaml
checks:
  <key>:
    exempt:
      enable: false
```

- 既定値は**全ての組み込み検査で `true`**、ただし [`commit-subject`](checks/commit-subject.md)
  だけ `false`（メッセージの体裁そのものを検証する検査なので、免除トレーラで体裁検証を
  回避できてしまうと矛盾するため）。
- [`worktree` 粒度](granularity.md)の検査（`doc-paths`, `consistency`, `doc-links`）は、
  免除トレーラの仕組み自体を持ちません（`enable` を書いても意味を持ちません）。

解決順は次の通りです（後段が優先）。

1. システム既定（検査の type ごとの `DefaultExemptEnable`）
2. `types.<type>.default.exempt`（type 全体の既定値の上書き）
3. `checks.<key>.exempt`（そのインスタンス個別の上書き）

## 書式のルール

```
<Trailer>: skip <理由>
```

- トレーラ名の大文字小文字は区別しません
- `skip` の後に**1 文字以上の理由が必須**です。理由が空の免除は拒否されます
  （「なぜ免除したか」を必ず残す運用を前提にしています）
- **トレーラはメッセージ本文の最後の段落（トレーラ段落）に書く必要があります。**
  git のトレーラと同じ扱いで、空行で区切ったときの最後のブロックの全ての行が
  トレーラの形（`<キー>: <値>`、または値が複数行にまたがる場合の空白始まりの継続行）
  をしている場合だけ、そこがトレーラ段落として認識されます。1 行でもトレーラの形で
  ない行が混じっていたり、subject しか無い（段落が 1 つしかない）メッセージだったり
  すると、トレーラ段落自体が無いものとして扱われ、免除は成立しません。本文の途中
  （最後の段落より前）に行頭が `<Trailer>: skip` で始まる文章を書いても、それは
  免除として扱われません。
- `git commit -v` がテンプレートに挿入するコメント行（`#` で始まる行）と、差分
  プレビューの区切り行（`# ------------------------ >8 ------------------------`）
  より後ろは、トレーラ判定の前に取り除かれます。コメントの中や差分プレビューの中に
  たまたま `<Trailer>: skip` の形の文章があっても免除にはなりません
  （core.commentChar を独自の文字に変更している場合は考慮していません。既定の `#` を
  前提にしています）。
- 同じトレーラを複数行書いても構いません。対象を絞らない全体の免除（後述）が
  1 つでもあれば、そのトレーラ段落全体で検査全体が免除されます。

### 免除の対象を絞る（スコープ付き免除）

検査によっては、免除の対象を検査の一部（doc-sync ならドキュメント単位）に絞れます。

```
<Trailer>: skip[<対象1>,<対象2>,...] <理由>
```

- 角括弧は `skip` の直後に**空白を挟まず**書きます（`skip [x] 理由` のように空白を
  挟むと角括弧付き構文として認識されず、理由の一部として扱われます）。角括弧と理由の
  間には空白が必要です
- 対象はカンマ区切りで、前後の空白は無視します
- 角括弧を省略した `skip <理由>` は従来どおり検査全体の免除です
- 対応している検査は現時点では [doc-sync](checks/doc-sync.md) だけで、対象は
  `pairs[].doc` のパスです。例:

  ```
  Doc-Sync: skip[docs/granularity.md] 内部の最適化で説明に影響しない
  ```

- スコープ付き免除に対応していない検査に書く、または対象が実在しない（書き間違い）場合は、
  検査を実行する前に error になります（[docs/principles.md](principles.md) の約束 7）。
  対象は正しいが、その対象に該当する違反が無い場合は error になりません（全体の
  免除で違反が無いのと同じ扱いです）
- どの検査がスコープ付き免除に対応しているか、対象が何の単位かは `spotter checks --json`
  の `exempt_scoped_supported` / `exempt_scoped_target_kind` から確認できます

## 粒度による違い

免除トレーラを「どのコミットのメッセージに書けば効くか」は、その検査の
[granularity](granularity.md) によって変わります。

- `squashed`: 範囲内のどのコミットに書いても良い（コミットごとにトレーラ段落を取り出し、
  範囲内のどれか 1 つのコミットに免除トレーラがあれば免除する。スコープ付き免除の対象は
  範囲内の全コミットの分を合わせた和集合）
- `per-commit`: 違反したそのコミット自身に書く必要がある
- `worktree`: 免除トレーラの仕組みが無い
